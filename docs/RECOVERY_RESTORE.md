# T-19.06 controlled checkpoint restore
restoreToNewDirectory authenticates and verifies an encrypted v1 checkpoint and expected commit string before writing to a newly created canonical absolute directory below an existing trusted parent. Allowed checkpoint UTF-8 filenames only. Exclusive writes, readback SHA-256, receipt written last. Never overwrite an existing directory. Partial output can remain without receipt on errors; inspect manually and do not import. No fsync, atomic rename, hostile-filesystem race protection, OS-level ACL verification, actual Git commit lookup or JSON semantic validation. Files are plaintext after decryption; use a private trusted local directory and appropriate OS permissions. No full backup of actual app/user data, SQLite/model restore, key storage or external recovery drill. Five local tests with actual temporary files and AES-GCM on Node 22.16 Linux. Windows/full suite pending. No deployments changed.
